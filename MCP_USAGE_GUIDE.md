# Керівництво з використання MCP для управління сайтом

## 📋 Огляд

Цей документ пояснює, як використовувати MCP (Model Context Protocol) інструменти для управління WordPress/Elementor замість кастомних PHP скриптів.

## 🔧 Налаштування MCP

### Поточна конфігурація

MCP сервер налаштований в `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "Elementor MCP": {
      "command": "npx",
      "args": ["-y", "elementor-mcp"],
      "env": {
        "WP_URL": "https://lawyermolochko.ddev.site:8443",
        "WP_APP_USER": "admin",
        "WP_APP_PASSWORD": "rJtC9nPsIC54LE0buyUjryzj"
      }
    }
  }
}
```

### Перевірка підключення

Якщо MCP не працює:
1. Перезапустіть Cursor повністю (закрийте і відкрийте знову)
2. Перевірте, що Node.js встановлений: `node --version`
3. Перевірте, що WordPress REST API доступний: `https://lawyermolochko.ddev.site:8443/wp-json/wp/v2/`

## 🛠 Доступні MCP інструменти

### 1. Отримання сторінки (get_page)

**Замість:** Ручне читання через `get_post()` або прямого доступу до БД

**Приклад використання:**
```
Отримай сторінку з ID 222
```

Або в коді:
```python
# MCP автоматично викличе mcp_Elementor_MCP_get_page(222)
```

**Переваги:**
- ✅ Безпечний доступ через REST API
- ✅ Автоматична обробка помилок
- ✅ Стандартизований формат даних

### 2. Оновлення сторінки (update_page)

**Замість:** `update-elementor-description.php`, `force-update-elementor-description.php`

**Приклад використання:**
```
Онови сторінку з ID 222, змінивши опис елемента 322ae9a на новий текст
```

**Попередні скрипти, які можна замінити:**
- ❌ `update-elementor-description.php`
- ❌ `force-update-elementor-description.php`
- ❌ `update-all-elementor-descriptions.php`

### 3. Створення сторінки (create_page)

**Замість:** Ручне створення через wp-admin або custom PHP скрипти

**Приклад:**
```
Створи нову сторінку з назвою "Нові послуги" з Elementor контентом
```

### 4. Оновлення сторінки з файлу (update_page_from_file)

**Замість:** Імпорт через PHP скрипти

**Приклад:**
```
Онови сторінку з ID 222 використовуючи дані з файлу page-data.json
```

### 5. Завантаження сторінки у файл (download_page_to_file)

**Замість:** Експорт через custom PHP скрипти

**Приклад:**
```
Збережи сторінку з ID 222 у файл backup-page-222.json
```

### 6. Видалення сторінки (delete_page)

**Замість:** Ручне видалення через wp-admin

**Приклад:**
```
Видали сторінку з ID 999
```

### 7. Пошук сторінки за slug (get_page_id_by_slug)

**Замість:** `get_page_by_path()` у PHP

**Приклад:**
```
Знайди ID сторінки за slug "services"
```

## 📊 Порівняння: Custom PHP vs MCP

### Custom PHP скрипт (старий спосіб)

```php
<?php
require_once(__DIR__ . '/wp-load.php');
$document = \Elementor\Plugin::$instance->documents->get(222);
$elements = $document->get_elements_data();
// ... складний код для оновлення ...
$document->save(['elements' => $elements]);
\Elementor\Plugin::$instance->files_manager->clear_cache();
?>
```

**Проблеми:**
- ❌ Потрібен прямий доступ до файлів WordPress
- ❌ Потрібно знати внутрішню структуру Elementor
- ❌ Складно обробляти помилки
- ❌ Не безпечно для production
- ❌ Потребує DDEV для виконання

### MCP інструменти (новий спосіб)

**Використання:**
```
Онови опис елемента 322ae9a на сторінці 222 на текст: "Новий опис..."
```

**Переваги:**
- ✅ Безпечний REST API доступ
- ✅ Працює з будь-якого місця (не потрібен DDEV)
- ✅ Автоматична обробка помилок
- ✅ Стандартизований інтерфейс
- ✅ Легко інтегрується з AI помічниками
- ✅ Версіоновані зміни через WordPress

## 🔄 Міграція з PHP скриптів на MCP

### Крок 1: Ідентифікувати скрипти для заміни

Кастомні скрипти, які можна замінити на MCP:

1. ✅ `update-elementor-description.php` → `update_page` MCP
2. ✅ `update-all-elementor-descriptions.php` → `update_page` MCP (з циклом)
3. ✅ `force-update-elementor-description.php` → `update_page` MCP
4. ✅ `update-via-mcp-api.php` → Безпосередньо використовувати MCP

### Крок 2: Перевірити роботу MCP

Спробуйте:
```
Отримай інформацію про сторінку з ID 222
```

### Крок 3: Поступова міграція

1. Почніть з простих операцій (читання сторінок)
2. Перейдіть до оновлень (update_page)
3. Використовуйте MCP для нових операцій
4. Старі скрипти можна залишити як backup (але не використовувати)

## 💡 Приклади використання

### Приклад 1: Оновлення опису елемента

**Старий спосіб:**
```bash
ddev exec php update-elementor-description.php
```

**Новий спосіб (MCP):**
```
Онови сторінку 222, змінивши опис елемента з ID 322ae9a на: 
"Отримайте безкоштовну консультацію від досвідчених юристів..."
```

### Приклад 2: Масове оновлення

**Старий спосіб:**
```bash
ddev exec php update-all-elementor-descriptions.php
```

**Новий спосіб (MCP):**
```
Знайди всі сторінки з елементами, що містять старий текст 
"Якщо вам потрібна допомога юриста" і онови їх на новий текст
```

### Приклад 3: Резервне копіювання

**Старий спосіб:** Ручне копіювання з БД

**Новий спосіб (MCP):**
```
Збережи всі сторінки з Elementor контентом у JSON файли для backup
```

## 📝 Нотатки

### Безпека

- ✅ MCP використовує Application Passwords (безпечніше ніж прямі SQL запити)
- ✅ Доступ через REST API (стандарт WordPress)
- ✅ Автоматична валідація даних
- ✅ Логування операцій

### Продуктивність

- ⚠️ MCP може бути трохи повільнішим через REST API (але не критично)
- ✅ Не потрібно завантажувати весь WordPress (`wp-load.php`)
- ✅ Кешування на рівні REST API

### Обмеження

- ⚠️ Потрібне підключення до інтернету (для REST API)
- ⚠️ Працює тільки з публічними API WordPress
- ✅ Але це стандартний спосіб роботи з WordPress

## 🚀 Наступні кроки

1. **Перевірте підключення MCP** - переконайтеся, що сервер працює
2. **Протестуйте прості операції** - спробуйте отримати сторінку
3. **Мігруйте по одному скрипту** - не намагайтеся все зразу
4. **Зберіть старі скрипти** - якщо знадобляться, але не використовуйте регулярно
5. **Документуйте процеси** - замість скриптів створюйте інструкції з MCP запитами

## ❓ Питання та відповіді

**Q: Чому MCP не підключається?**  
A: Перезапустіть Cursor повністю. Перевірте конфігурацію в `~/.cursor/mcp.json`.

**Q: Чи можна використовувати і PHP скрипти, і MCP?**  
A: Так, але для нових операцій краще використовувати MCP.

**Q: Що робити, якщо потрібна функція, якої немає в MCP?**  
A: MCP підтримує стандартні операції WordPress REST API. Для спеціальних потреб можна додати custom endpoints.
